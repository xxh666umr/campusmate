### 3.2 鉴权 URL 生成（对照《WebSocket 协议通用鉴权 URL 生成说明》1.2）

| 检查项 | 官方要求 | 代码实现（`buildAuthUrl()`，现文件 150-174 行） | 结论 |
| --- | --- | --- | --- |
| date | RFC1123，时间偏差 ≤ 300s，UTC/GMT | `gmdate('D, d M Y H:i:s') . ' GMT'` | ✅ |
| 签名原文 3 行 | `host: {host}\ndate: {date}\nGET {path} HTTP/1.1` | 完全一致；path 不带 query | ✅ |
| 签名算法 | `hmac-sha256(APISecret, tmp)`，再 base64 | `base64_encode(hash_hmac('sha256', $origin, $api_secret, true))` | ✅ |
| authorization 原文 | `api_key="...", algorithm="hmac-sha256", headers="host date request-line", signature="..."` | `sprintf` 逐字一致（含空格与引号） | ✅ |
| authorization | base64(authorization 原文) | `base64_encode($authorizationOrigin)` | ✅ |
| 最终 URL | 三个参数 `authorization` / `date` / `host` 做 urlencode | `http_build_query()`（与官方 PHP 示例同函数，输出 `date=Fri%2C+05+May...` 形式） | ✅ |
| 实测验证 | —— | 本机实测服务端能解出 api_key（返回 “apikey not found” 而非 400 参数错误） | ✅ 正确解析 |

### 3.3 WebSocket 握手

| 检查项 | 官方/RFC 要求 | 代码实现（`handshake()`，现 174-218 行） | 结论 |
| --- | --- | --- | --- |
| 请求行 | `GET {path}?{query} HTTP/1.1` | 一致 | ✅ |
| 必备头 | `Host`、`Upgrade: websocket`、`Connection: Upgrade`、`Sec-WebSocket-Key`（16 字节随机 base64）、`Sec-WebSocket-Version: 13` | 全部具备（另有 User-Agent） | ✅ |
| 响应判定 | `HTTP/1.1 101 Switching Protocols` | 正则校验 101；非 101 抛异常 | ✅ |
| Accept 校验 | RFC 6455：客户端**必须**校验 `Sec-WebSocket-Accept = base64(sha1(key+GUID))` | 原代码只检查响应头“存在”，未校验值 → **已补丁**（第 4.2 节） | ✅ 补丁增强 |
| 101 后残留字节 | 服务端可能把第一帧与 101 响应放在同一 TCP 段 | 原代码丢弃 → **已补丁**（第 4.3 节） | ✅ 补丁增强 |
| 失败原因 | 便于排错 | 原代码只保留状态行，401 的 JSON 原因丢失 → **已补丁**（第 4.1 节） | ✅ 补丁增强 |

### 3.4 帧编解码

| 检查项 | 要求 | 代码实现 | 结论 |
| --- | --- | --- | --- |
| 客户端发帧掩码 | RFC 6455 必须掩码 | `writeFrame()` 随机 4 字节掩码逐字节 XOR | ✅ |
| 长度编码 | <126 单字节；126 用 2 字节大端；127 用 8 字节大端 | `pack('n')` / `pack('J')`，与大端序一致 | ✅ |
| 服务端帧 | 不掩码 | `readFrame()` 支持掩码/非掩码两种情况 | ✅ |
| PING/PONG | 收到 ping 回 pong（同 payload） | opcode 0x9 → `writeFrame($data, 0xA)` | ✅ |
| CLOSE | 收到 close 结束读取 | 结束循环；原代码丢弃 close 原因 → **已补丁**（第 4.4 节） | ✅ 补丁增强 |
| 分片（FIN=0 续帧） | 可选能力 | 当前未做续帧重组（星火响应为单帧，实测未触发） | ⚠️ 已记录为限制，见第 9 节 |
| 读超时 | 防止永久阻塞 | `stream_set_timeout` + `stream_get_meta_data()['timed_out']` 判定 | ✅ |

## 4. 修改补丁（文件 + 行号 + 旧串 + 新串 + 官方依据）

> 说明：成功调用路径（签名、payload、帧、结束条件）本身**没有发现必须修的 bug**；以下 5 处均为“实测暴露的排错信息缺失/协议健壮性”问题，改动小且不改变成功路径行为。修改文件均为 `app/Spark/SparkClient.php`，修改后 `php -l` 通过、`php tools/test_spark.php` 与降级实测均正常。

### 4.1 握手失败时丢失服务端原因（实测触发，用户可感知）

- 位置：`handshake()`，现文件 174-246 行（原 182-187 行）
- 旧串：
```php
if (!preg_match('#^HTTP/1\.1\s+101#', $response)) {
    throw new \RuntimeException('星火 WebSocket 握手失败：' . strtok($response, "\r\n"));
}
```
- 新串（节选，完整实现见 216-240 行）：
```php
if (!preg_match('#^HTTP/1\.1\s+101#', $headers)) {
    throw new \RuntimeException('星火 WebSocket 握手失败：' . $this->describeHandshakeFailure($fp, $headers, $leftover));
}
```
其中 `describeHandshakeFailure()` 按 `Content-Length` 补读响应体，并优先取 JSON 的 `message` 字段。
- 依据：讯飞在鉴权失败时返回 `HTTP/1.1 401` + JSON 响应体（本机实测为 `{"message":"HMAC signature cannot be verified: apikey not found"}`）；原实现只留状态行，用户/日志看不到“到底哪不对”。
- 实测效果：
  - 修补前日志：`星火 WebSocket 握手失败：HTTP/1.1 401 Unauthorized`
  - 修补后日志：`星火 WebSocket 握手失败：HTTP/1.1 401 Unauthorized（HMAC signature cannot be verified: apikey not found）`

### 4.2 未校验 `Sec-WebSocket-Accept`

- 位置：`handshake()`，现文件 207-212 行（原 185-187 行）
- 旧串：
```php
if (!str_contains(strtolower($response), 'sec-websocket-accept:')) {
    throw new \RuntimeException('星火 WebSocket 握手响应缺少 Sec-WebSocket-Accept');
}
```
- 新串：
```php
// RFC 6455：客户端必须校验 Sec-WebSocket-Accept
$expected = base64_encode(sha1($key . '258EAFA5-E914-47DA-95CA-C5AB0DC85B11', true));
if (!preg_match('/^sec-websocket-accept:\s*(\S+)/mi', $headers, $matches) || !hash_equals($expected, $matches[1])) {
    throw new \RuntimeException('星火 WebSocket 握手失败：Sec-WebSocket-Accept 校验不通过');
}
```
- 依据：RFC 6455 §4.1；官方文档亦要求“必须符合 websocket 协议规范（rfc6455）”（服务说明第 1 条）。

### 4.3 101 之后残留字节被丢弃（潜在丢帧）

- 位置：`handshake()` 216 行 + `readBytes()` 313-319 行
- 旧串：
```php
$this->readBuffer = '';
```
（原实现只读“直到 `\r\n\r\n`”，把同一 TCP 段里 101 之后的数据直接丢弃）
- 新串：
```php
// 101 之后可能紧跟第一帧，缓存起来交给 readFrame，避免丢帧
$this->readBuffer = $leftover;
```
```php
private function readBytes($fp, int $n): string
{
    $buffer = '';
    if ($this->readBuffer !== '') {
        $take = min($n, strlen($this->readBuffer));
        $buffer = substr($this->readBuffer, 0, $take);
        $this->readBuffer = substr($this->readBuffer, $take);
    }
    while (strlen($buffer) < $n) { /* 原逻辑不变 */ }
```
- 依据：WebSocket 帧是字节流，101 响应与第一帧之间没有 TCP 分段保证；提前消费掉会永久丢字节。

### 4.4 close 帧原因被丢弃

- 位置：帧循环 101-104 行 + 空内容报错 142-145 行 + 新增 241-250 行
- 旧串：
```php
if ($opcode === 0x8) {
    break;
}
```
```php
if (trim($content) === '') {
    throw new \RuntimeException('星火未返回有效内容');
}
```
- 新串：
```php
if ($opcode === 0x8) {
    $this->closeInfo = $this->describeCloseFrame($data);
    break;
}
```
```php
if (trim($content) === '') {
    $hint = $this->closeInfo !== '' ? '（' . $this->closeInfo . '）' : '';
    throw new \RuntimeException('星火未返回有效内容' . $hint);
}
```
- 依据：服务端可能用 close 帧（带 code/reason）结束会话；把原因带进日志，用户才能在「日志管理」页面直接看到 1008/1011 等线索。

### 4.5 密钥首尾空格导致签名失败

- 位置：构造函数，现文件 19-28 行
- 旧串：
```php
public function __construct(array $cfg)
{
    $this->cfg = $cfg;
}
```
- 新串：
```php
public function __construct(array $cfg)
{
    // 控制台复制密钥时容易带上首尾空格，统一去掉，避免签名对不上
    foreach (['app_id', 'api_key', 'api_secret'] as $key) {
        if (isset($cfg[$key]) && is_string($cfg[$key])) {
            $cfg[$key] = trim($cfg[$key]);
        }
    }
    $this->cfg = $cfg;
}
```
- 依据：`authorization` 原文直接拼 `api_key`/`api_secret`，多一个空格就会 401；这是“复制粘贴密钥”最常见的失败原因。

## 5. 无密钥 / 错误密钥实测记录

| 用例 | 配置 | 结果 | 日志 |
| --- | --- | --- | --- |
| A. 无密钥（用户当前默认场景） | `provider=auto`，三个密钥为空 | `providerStatus = {provider: mock, label: 本地演示引擎}`；`/chat` 页面含「本地演示引擎（未配置密钥）」「未检测到星火密钥」；`POST /api/chat` → `200, ok=true, provider=mock`，回答 195 字 | 写 `chat.single`；**不写** `ai.spark.failed`（因为根本没有发起星火请求，属正确行为） |

## 6. 给用户：填密钥步骤（精确到字段）

### 6.1 获取密钥

1. 打开 <https://console.xfyun.cn/> 登录讯飞开放平台；
2. 进入「星火认知大模型」→「服务管理 / 我的应用」，选择或创建应用；
3. 在应用详情页复制三个值：**APPID**、**APIKey**、**APISecret**；
4. 确认已开通 **Spark Max**（对应 v3.5，免费额度也需领取）。

### 6.2 写入配置（只改一个文件）

新建 `smart-service/app/config.local.php`（已在 `.gitignore`，不会被提交）：

```php
<?php
return [
    'spark' => [
        'app_id'     => '这里填 APPID',      // 8 位十六进制
        'api_key'    => '这里填 APIKey',     // 32 位十六进制
        'api_secret' => '这里填 APISecret',  // 32 位十六进制
        'url'        => 'wss://spark-api.xf-yun.com/v3.5/chat',
        'domain'     => 'generalv3.5',
        'temperature'=> 0.5,
        'max_tokens' => 2048,
        'timeout'    => 30,
    ],
    'provider' => 'auto', // auto：有密钥走星火、失败自动降级；mock：只用本地引擎
];
```

> 注意：如果该文件已存在（例如队友配了 MySQL），**只追加/合并 `spark` 与 `provider` 两项**，不要覆盖 `db` 配置。

### 6.3 验证

```bat
cd /d D:\...\smart-service
C:\xampp\php\php.exe tools\test_spark.php
```

- 退出码 0 + 「✓ 生产类调用成功」= 成功；
- 浏览器刷新 → 登录 → 「智能客服」，右上角应显示 **「讯飞星火在线」**，页内「当前引擎」卡片显示 `spark`。

### 6.4 回退

删除 `app/config.local.php` 中 `spark` 的三个值（或把 `provider` 改为 `mock`），刷新页面即回到本地演示引擎。
真实调用失败（如欠费、审核拦截、网络抖动）也会自动回退，页面不会中断。

## 7. 自测脚本 `tools/test_spark.php`

- 位置：`smart-service/tools/test_spark.php`（纯 PHP、无 Composer 依赖）
- 说明文档：`smart-service/tools/spark_selftest.md`
- 能力：环境检查 → DNS → TCP/TLS（含服务器证书）→ 鉴权 URL 生成（可脱敏展示）→ WebSocket 握手（含 Accept 校验、401 响应体）→ 逐帧摘要 → 最终答案/token 用量/sid → 用生产类 `App\Spark\SparkClient` 复测
- 超时：`--timeout=15` 可控（默认 15s）
- 退出码：0 成功 / 2 缺密钥 / 3 网络或 TLS / 4 握手 / 5 业务错误码 / 6 空内容
- 无密钥时可 `--dry-run` 仅校验配置；实测命令（伪造密钥）也用于本次核查，返回 401 并给出中文排查建议。

```bat
C:\xampp\php\php.exe tools\test_spark.php --app-id=... --api-key=... --api-secret=...
C:\xampp\php\php.exe tools\test_spark.php --dry-run
C:\xampp\php\php.exe tools\test_spark.php --insecure   # 仅排查 CA 问题
```

## 9. 风险与已知限制

| 风险/限制 | 影响 | 建议 |
| --- | --- | --- |
| 真实密钥成功链路 | 当前未配置密钥，因此没有真实回答入库 | 拿到密钥后运行 `tools/test_spark.php`，10 秒内即可确认（会逐帧打印 + 用生产类复测） |
| 星火 Max 套餐下线公告（2026-03-10） | 届时 v3.5 可能返回 10404/10016 | 按第 8 节把 `url`/`domain` 切到 Ultra |
| 未实现 WebSocket 分片（FIN=0 续帧）重组 | 若响应被分片，可能丢部分内容；当前实测与官方实现均未出现 | 属已知限制，如遇长回答截断再补 |
| 内容审核（10013/10014）会返回错误 | 问题被审核拦截时降级本地引擎 | 属预期；日志可查错误码 |
| 累计/增量文本兼容用启发式判断 | 极端情况下可能误判 | 官方 v3.5 返回增量文本；自测脚本会打印每帧 delta 便于核对 |
| 密钥安全 | 泄露可被他人消耗额度 | 只写 `config.local.php`（已 gitignore），不截图、不提交；泄露后控制台重置 |
| 降级时用户可能误以为“真在用大模型” | 页面有引擎标签提示，但回答内容本身不区分 | 右上角/「当前引擎」卡片已明示；答辩时主动说明为演示模式 |
